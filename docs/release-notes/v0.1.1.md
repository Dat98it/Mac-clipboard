# Mac ClipBoard 0.1.1

Bản sửa lỗi: panel lịch sử giờ đi theo desktop (Space) bạn đang dùng.

## Có gì

- **Sửa lỗi panel kẹt ở desktop cũ.** Trước đây, mở Mac ClipBoard ở desktop 1 rồi sang desktop 2 bấm ⇧⌘V (hoặc bấm icon trên thanh menu) thì panel vẫn nằm ở desktop 1 và không dán được. Nguyên nhân: panel mở ở desktop khác vẫn được tính là "đang hiện", nên phím tắt ẩn nó đi thay vì kéo về. Giờ:
  - panel mở ngay trên desktop hiện tại, kể cả khi bạn đang ở một app toàn màn hình;
  - ⇧⌘V và icon chỉ ẩn panel khi nó đang hiện ở desktop bạn đứng; từ desktop khác thì luôn đưa panel về đây và ghi nhận app đang dùng làm nơi dán.

## Cài đặt

Mở `MacClipBoard-0.1.1.dmg`, kéo Mac ClipBoard vào Applications (thay bản cũ). App ký ad-hoc, chưa notarize: lần đầu mở, bấm **Done** (đừng bấm "Move to Trash"), rồi vào **System Settings → Privacy & Security → Open Anyway**. Bản universal, chạy trên Apple Silicon và Intel, macOS 14 trở lên.

Bản ký ad-hoc mới có CDHash khác, nên có thể phải cấp lại quyền **Trợ năng** (Accessibility). Lịch sử clipboard giữ nguyên khi cập nhật.

Kiểm tra file tải về bằng mã SHA-256 trong file `.sha256` đính kèm.

## Đã kiểm thử

- 131 test tự động (thêm 3 test cho quy tắc ẩn/hiện panel) và 3 đột biến mới đều bị test bắt.
- Đo trên máy thật với hai desktop, ở chế độ `--sandbox`: bản 0.1.0 để panel ở lại desktop cũ khi bấm icon từ desktop khác; bản này chuyển panel sang desktop đang dùng.

## Hạn chế đã biết

- Việc dán thật sau khi panel được kéo về desktop khác chưa được chạy đầu-cuối; phần mở/dán không đổi so với 0.1.0.
- Phím tắt ⇧⌘V dùng chung đoạn code đưa panel lên với icon thanh menu; phép đo dùng icon vì phím tắt trong bản thử sẽ tranh với app thật.
- Các hạn chế của 0.1.0 vẫn còn (Teams trên trình duyệt không nhận file không phải ảnh khi dán; hộp xin quyền Desktop và mở lúc đăng nhập chưa kiểm chứng đầu-cuối).
